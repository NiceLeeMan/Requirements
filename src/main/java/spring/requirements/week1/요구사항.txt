작업 배경
애플리케이션을 개발하다 보면, 연관관계를 가진 서로 다른 두 테이블의 데이터를 조회해 하나의 응답 객체로 만들어야 하는 상황이 빈번하다.
이를 해결하기 위해 JOIN이나 테이블별 개별 쿼리 등 여러 방식을 사용할 수 있지만, 구현 과정에서 부주의하면 N+1 문제가 발생하기도 한다.
이번 실습에서는 각 방식을 직접 구현하고 쿼리 실행 과정을 관측하여, 상황에 적절한 조회 방식을 선택할 수 있는 기준을 정리하고자 한다.

요구사항 기능

주문내역을 화면을 만드는 것이며, 아래의 조건을 지켜야함

1) "주문"을 리스트 형태로 나타낼 것
2) 각 주문은 주문정보, 상품 정보를 포함하는 UI로 구성해야함.
2-1) 주문정보는 다음과 같은 데이터를 포함해야한다
- 주문 번호 (1)
- 주문 날짜 (1)
- 주문 상태 (1)
- 상품 정보 (N)

3) 상품 정보는 다음과 같은 데이터를 포함한다
- 상품 명
- 상품 수량
- 상품 가격
